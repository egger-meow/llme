# LLMe 的個人 Graph 與情境 Tree

**設計審核稿 v0.4 · 2026-11-23。** 已確認可寫有原話支撐、明標為推論、本人可以糾正的主張。本版區分研究者原意中的大情境（角色或議題）、議題內的局部條件，以及各節點能展開的關係圖。架構仍待審。W7 問「少量互動後，能不能預測這個人下一次怎麼選？」因此，每個判斷都要能回答三件事：**這是誰對誰的看法？換什麼條件還成立？憑哪句話這樣寫？** HugAgent 第一輪先檢驗這種表示對預測有沒有幫助。[W7 第 6–12 頁](../meetings/W7.pdf#page=6) · [W8 第 9–11 頁](../meetings/w8.pdf#page=9)

## 從上到下看一個人：大情境 → 局部條件與例外 → 關係圖

根是「這個人的所有情況」。HugAgent 可以用三個官方議題當它的直接子節點。研究者原本舉的「當爸爸」與「當工廠管理員」是另一種同樣大的入口，以生活角色來切。角色與議題可以交叉。例如「以爸爸身分談校園攝影機」同時涉及爸爸和公共監控；從兩個入口可讀到同一條有據的主張。HugAgent 第一輪只預設資料已給的議題。當事人在資料中以什麼身分表態，要另有原話根據。

```text
P46 的所有情況
├─ 醫療
├─ 公共監控
└─ 都市分區
   └─ 允許提高開發密度              → 此處可開圖，看到他預期交通多半更塞
      └─ 大眾運輸更容易搭，而且便宜  → 此處可開圖，看到更多人改搭與交通持平
```

可把這個讀法記成 **Tree → Tree → Graph**。中間的局部節點由訪談裡有意義的條件長出；若只看到「在 X 時他怎麼想」，一條局部主張就已足夠。若還知道「在 X 時他改用哪條判斷」，就在同一份資料中把局部主張連到被覆寫的一般主張。上例最後一枝既能從「何時交通會持平」找到，也能從「『多半更塞』有什麼例外」找到。有多層覆寫時可沿主張展開例外樹，只有一條時保留連結即可。這使每個大情境都能放局部情境和例外，無須替每個節點預建兩棵空樹。

**Graph 可以在任何有材料的節點打開。** 節點選出本地的主張、適用的一般主張、例外及證據，沿用同一個概念與主張 ID。各節點可有不同取捨，例如「安全」可以共用，而「安全優先於產量」須在相應的角色與條件下有依據。P46 的交通例子只表達因果預期，訪談沒有在這一句比較兩個價值，因果邊就足夠。最上層也可以容納有證據的一般主張；把所有材料分到同一個人名下，本身不足以推得跨角色通用的價值排序。

個人根節點和三個議題供研究者瀏覽。正式作答由 host 先綁定該題允許的訪談，所有節點檢視都受這個範圍限制。同一人同一議題下也可能有多份可見材料；首輪維持逐題的 Raw／Graph／Flat 對照。[第一輪資料邊界](hugagent/prepared-data.md)

## 先看一個真的會長出例外的例子

P46 談**都市分區允許提高開發密度**。他預期這樣通常會讓交通更塞，又主動補充，**如果大眾運輸更容易搭，而且便宜**，更多人會改搭大眾運輸，他認為交通就會維持原狀。下面是研究者對同一段訪談的中文轉述與示意，英語原文保留在本機。可從都市分區 T2-0311 的可見訪談找到第 5 段。這裡使用的是建圖時就能讀到的聊天內容。[P46 的可見訪談，第 139 列 e005](../ref/HugAgent/prepared/inputs/histories.jsonl#L139) · [資料來源及使用範圍](hugagent/prepared-data.md)

```text
提高都市開發密度
│  R1  P46 預期交通多半更塞
└─ 大眾運輸更容易搭，而且便宜
   R2  他預期交通維持原狀     ← 在這個條件下取代 R1
   R3  他預期更多人改搭大眾運輸，是他給 R2 的理由
```

這個例子有三個設計上的分界。只知道「便宜」時，還缺「更容易搭」，系統應保留條件未定。從「增加」改判「持平」已經值得長例外枝，無須變成「減少」。P46 談的是**交通結果**，對他本人是否支持提高密度仍然是另一個問題。

### 回到你的工廠案例

W7 的人選 A 維持現狀，說「可能永久受傷，我就不增產」。先存**這個人在這個情境選 A 勝過 B**。若他沒說「風險比收益重要」，這個解釋要以推論身分留下；也可能另有他沒有說出的考量。若他還親口說「通常我願意為增產承擔風險，唯獨可能永久傷人時我不接受」，才有一條可被這次例外覆寫的一般規則。反過來，如果他原話只說「風險**可逆**時我願意」，永久傷害根本不在那條規則的範圍內，兩個子情境應該並列。這正是「有不同處理才長 child」需要講清楚的判準。[W7 第 7–11 頁](../meetings/W7.pdf#page=7)

## 同一個父節點下，左邊因例外而長，右邊因子情境而長

v0.1 把「哪些情境包含哪些情境」與「哪些判斷覆寫哪些判斷」分開畫。v0.2 用 P46 說明一個節點能兼有兩種意義，但該例只有一枝，無法檢驗遇到兩個兄弟分支時怎麼選。以下是延伸自 W7 的假設案例。

```text
工廠接單　R：通常願意增產
├─ 因例外而長：若有永久傷害風險，這張單就不增產（覆寫 R）
└─ 因子情境而長：夜班（本人另外說，夜班一定要多做一次巡檢）
```

問「今晚這張單可能永久傷人，要不要增產？」若選了夜班就只往右走，會漏掉左邊明說的例外。反過來，只要進夜班就套用左邊，又會把所有夜班都當成會永久傷人。這題可同時得出「不增產」及「夜班多一次巡檢」。若只知道是夜班，是否增產只能按 R 暫判，並標記缺少風險條件。若另有「趕急單一律增產」和風險規則同時成立，兩者對同一決定相衝，就要找本人怎樣取捨的證據；換成兩棵樹也無法據此填出答案。

**建議的讀法。** 用情境找當下涉及的規則；每次要沿用 R，就用當下的全部已知條件檢查「哪些例外會改 R」。即使例外畫在兄弟位置也能找到，無須把它抄進每個兄弟。v0.1 分開兩種關係有推理上的理由。例外少時，R 旁的一份例外清單已足夠；若例外本身還有例外，才需要展開成樹。螢幕可合併顯示，但單靠選一個 child 往下走，只有在分支互斥或已明訂每種交集怎樣處理時才可靠。

**本人重視的抽象概念放哪裡？** 「安全」在個人 Graph 裡可有一個共用 ID。若兩段原話分別支持「在工廠考量員工安全」與「在醫療考量病人安全」，兩個情境都可連到它，各自保留證據和對象。若要寫「他通常把安全放在收益之前」，這是另一條需要證據的比較主張。只有這類具有適用範圍與結論的主張能被例外覆寫。概念可以共用，優先順序要另行驗證；HugAgent 每題仍只從該題允許的訪談取證。

| 可行架構 | 能直接回答 | 會付出的代價 |
|---|---|---|
| 每個情境節點各存一張完整圖 | 「打開工廠／夜班，這人怎麼想？」閱讀直觀，貼近 W7 草圖 | 同一條原話與規則可能複製多次。改正一次誤讀，其他分支的副本也要跟著改；夜班和永久風險可以交疊，單一父節點難選。 |
| **有證據的 Graph 為底，情境按包含關係查，例外按被改寫的規則查** | 從情境或規則任一端都可找到同一條主張，並點回原話 | 查規則時仍須比對完整條件，條件重疊時可能同時命中多條。**這是本稿提議。** |
| 一張帶條件的平面規則表 | 容易人工讀、驗引文；也能列出兩條規則各自適用的條件 | 要看哪些概念或證據反覆出現在不同判斷，得逐列重找。它也是將來檢驗 Tree 是否值得的對照。 |

在建議的設計裡，**打開某個情境就等於打開它的子圖**。畫面列出當地的主張、可沿用的父規則、在這裡被替換的規則，以及各自證據。上層可以把整個工廠子圖折成一個節點；展開後仍回到原本那些 ID。假如未來想把「工廠怕永久傷害」和「理財要留生活預備金」連成「優先避開承擔不起的損失」，這需要一條有來源、可被推翻的**新推論**。將兩個子圖收合只改變畫面，不會自動替人歸納出人格。[W7 第 9–10 頁](../meetings/W7.pdf#page=9)

## Graph 裡具體存什麼

| 物件 | 存下的內容 | 判讀原則 |
|---|---|---|
| **Evidence 原話** | 一次可見問答或其他資料來源中的一段話。保留發問者與回答者、原序、原文、可定位的引文。 | 遇到「對」要同時引用問題與回答。只有訪談者提出的假設，沒有本人回應，不能算作本人認同。 |
| **Concept 概念／選項** | 人在談的考量、結果、目標或兩個可選方案。別名保留用詞與出處。 | 比較「安全 vs. 收益」與「維持 vs. 增產」要用不同端點。語義相似只足以提議對照，合併須有同一指涉的依據。 |
| **Condition 情境條件** | 有名字的條件及組合。區別「全部成立」「任一成立」「明確否定」，保留原詞、適用對象與出處。 | P46 說「容易搭且便宜」，兩項都成立才符合。未說、明確否認、確知成立分開記錄。 |
| **Claim 可單獨引用的主張** | 誰持有這個看法、談的是誰、關係、帶角色的端點、方向或結果、程度詞、適用條件、哪些字支持它。 | 同一段原話可支持數條主張；不同主張也可以互有支持或反證。這讓「人＋兩個考量＋條件＋證據」可以用一個有 ID 的多元關係表達，儲存方式可稍後選。 |

**兩種「範圍」容易讀錯。** 資料包現有的 `scope_id` 指「這次能讀哪份訪談」，是權限邊界；下文用 `condition_id` 表示「某句判斷在什麼情境成立」。一份 20 段訪談裡可以有多個情境；兩份訪談即使都談同一個情境，也各自只能引用自己看到的原話。

**主張的語彙先小一點。** `influences` 記本人認為 X 會使 Y 上升、下降、持平或方向不明；`stance_on` 記對某標的的立場；`reports_experience` 記經驗、頻率與感受，可保留「有時覺得更安全」；`prefers_over` 記兩個方案的比較；`more_important_than` 記本人怎樣比較兩個考量。一次選擇須保留當次方案、條件與題意，只有資料確實呈現了 A、B 兩個選項才寫 A 勝 B。支持程度與理由影響力各有標的和量尺。本人若在可見訪談明說數字就連原單位保存，只說「非常強」就保留原詞。問卷金標隔離於評分端。

一條 Claim 至少區分下列幾個維度，讓讀者可以逐一挑錯。

| 維度 | 例子或預設 |
|---|---|
| 發話者、信念持有人、被描述的對象 | 訪談者問、P07 回答；P07 **認為**有隱私疑慮的**一般人**較不支持監控。三個角色均可回查。 |
| 根據與抽象程度 | `explicit` 為忠實轉述。已確認容許有原話支撐的推論，寫入和讀出時都明標 `inferred`，附引文、所依據的主張與簡短理由，保留適用條件。本人可以逐條糾正。跨域人格歸納留待另行研究。 |
| 適用性與時間 | 區分一次事件、本人自述通常如此、以及範圍未知。觀察時間、本人說的適用期間、系統何時寫入分開；未知可空。推論跨度與持續多久各自標記。[W8 第 4–6 頁](../meetings/w8.pdf#page=4) |
| 比較與不確定性 | 比較記錄存 `compare_options`（方案）或 `compare_factors`（考量）及 `result = left / right / equal / incomparable`；前述 `prefers_over`、`more_important_than` 是嚴格高低的讀法。同等、本人表示不可比較均須有證據。缺資料由讀取端回「未知」。在同條件出現 A 勝 B、B 勝 C、C 勝 A，保留三筆原始比較。預設不做傳遞閉包，也不從一次選擇估全人共用的權重。 |
| 規則的適用方式 | 單次觀察只留在原情境；明示「通常」「一般來說」等才可成為可沿用的預設。即使同一句明說「通常」，其個人可信度與廣泛適用性仍可接受反證。 |

這保留了 W7 對 weight 的質疑，也借用了 TCP-nets 把「偏好哪個方案」與「兩個屬性誰較重要」分開處理的想法。這裡額外要求能追到本人證據，並容許衝突留存。[W7 第 7–8 頁](../meetings/W7.pdf#page=7) · [Brafman 等人的 TCP-nets 論文](https://arxiv.org/abs/1109.6345)

## Tree 如何生長、沿用與覆寫

**什麼時候長 child？** 訪談給了一條要限定在更窄條件的判斷，就在那個子情境記下。本人也可能直接說出一條一般規則和它的例外，這時可以因例外建立 child。節點代表符合條件的一組情況，`subcontext_of(child_condition, parent_condition)` 表示嚴格包含，例如「工廠且夜班」落在「工廠」內。只知道夜班時他會怎麼選，父層的一般偏好就留白。首次建立的緣由記在操作紀錄。若同一條件已存在就沿用相同 ID，日後才發現例外，直接補連結。撤回例外時，有獨立證據的子情境和局部觀察仍可保留。

**集合怎麼放進樹？** 對某條一般規則 R，可以把「會使 R 改判的情況」看成 R 適用範圍內的一個子集。每條一般規則各有自己的例外範圍。同一夜班節點可以覆寫增產決定，又補充一項先前未知的巡檢安排。另一種交集發生在條件本身，例如「夜班」和「可能永久傷人」可以同時成立。原話確實談到兩者同時成立時，交集只建一個節點；樹上選一條路展開，另一處放連到同一個節點的捷徑。查詢按實際符合的條件取值，畫面安排不決定規則優先序。

**怎麼標例外？** 在節點裡用 `exception_of(local_claim, default_claim)` 指定所改的規則，這條規則可以在更上層的祖先。檢查原話是否支持一般規則及涵蓋的子條件、是否在談同一個人的同一項判斷、局部結果改了什麼，以及兩者的覆寫關係有什麼證據。畫面的「有例外」依有效連結顯示。本人明說「通常……除非……」可標明示。兩個不同情境剛好答得不同，可列成待核候選。第一輪是否只採用有明示依據的覆寫，仍待審。程度改變也可有意義，例如「通常強烈支持，遇到 X 就只稍微支持」，須保留原詞及相同的程度維度。問卷分差本身只在評分端出現。

**給定新情境時怎麼讀**（供未來 Tree 路由，以及研究者手動檢查）。

1. 題幹條件進入此次查詢的暫存區。比對每個條件，回傳「成立／明確不成立／資訊不足」。組合依且、或、非計算；未提到的事維持未知。
2. 取與問題主體和判斷相符的局部觀察、適用的預設，以及可能生效的例外。只有成立且已被支持的例外，才能在本次查詢用局部規則取代指定的父規則。其他議題與理由仍可沿用。
3. 若某個例外條件未知，父規則可列為暫定，並顯示缺的條件。兩條都成立的例外意見相反時，只有有證據的明確優先關係才能裁決。同一條覆寫鏈可以繼續往下，互不包含的兄弟各保留。深度、寫入先後或 LLM 自評信心都不能自動打破平手。
4. 傳回「可用結論、候選／未解、沿用或覆寫路徑、缺少的條件、證據 ID」。HugAgent 作答時，模型仍依原題交 A/B 或量尺內一個整數。研究者可以同時知道這個數字背後的證據有多不完備。**第一輪三組正式作答都不額外執行這套路由。**

以下用 P46 的**同一版規則**檢查讀樹的人會得到什麼。前三個自造查詢改變大眾運輸條件，最後一個改變所問的判斷。

| 查詢時已知 | 應傳回的規則與理由 |
|---|---|
| 更容易搭，而且便宜 | R2 適用；R1 在這次被覆寫。可另讀 R3 看本人給的理由。 |
| 便宜，明確說沒有比較容易搭 | R1 適用；R2 所需的組合條件不成立。 |
| 只提到便宜 | 暫列 R1，同時標出 R2 仍可能生效；缺的資訊是是否更容易搭。 |
| 改問「本人支持提高密度嗎？」 | R1、R2 都在預測交通結果。可作思考線索，沒有一條能直接回答他的政策立場。 |

**更新對應到不同的事。** 新證據支持同一主張就新增支持；反證先並存。更正誤讀只撤回原來的解讀，留下被撤回版本，檢查依賴它的推論與覆寫邊；尚有獨立依據者重新評估。局部例外只改在那個條件下怎麼讀。本人明說同條件下「以前……現在……」才建立有時間根據的 `supersedes`。W8 的上週普通風險選增產、本週永久傷害選維持，同時改了條件與時間；漂亮的樹也無法替研究者補上「本週碰到普通風險會怎麼選」。[W7 第 12 頁](../meetings/W7.pdf#page=12) · [W8 第 11 頁](../meetings/w8.pdf#page=11)

## LLM 的讀寫接口

以下是建議的本機工具契約。模型提議「這句該怎麼理解」，host 負責資料權限、驗證、提交與重播。同一工具參數可用原生工具呼叫或結構化 JSON 傳遞。先把語義訂清楚，傳輸方式可替換。

| 角色／操作 | 傳入 → 傳回 | 邊界 |
|---|---|---|
| Host 開建圖工作階段 | 從資料包取一個 `scope_id` → 固定順序的 `e001…`、英文 Q/A、工具型別 | builder 只看到這份允許訪談。人物 ID、其他訪談、原始跳號、人口背景、目標題與答案均由 host 留在各自工作階段。 |
| Builder · `evidence_read` | 本工作階段的 evidence IDs → 原始 Q/A 及可引用欄位 | 小訪談直接隨初始訊息給全份。這個操作可重讀已准許的原話。 |
| Builder · `graph_propose` | `request_id, expected_revision, operations[]` → `draft_id, base_revision` 或逐項錯誤 | 同一批可先宣告暫時 concept／condition／claim ID，再引用它。空批次附 `no_supported_claims` 表示讀完但缺少依據。 |
| Host · `graph_commit` | 已驗證 draft、預期 revision → 新 revision、穩定 ID 對照、事件序號 | 整批成功才改圖。若需下一批，host 帶回同一工作階段的 revision、已提交物件及穩定 ID 對照。host 凍結完成的版本；已失敗的建構不能當作一張合法空圖。 |
| Host／研究者 · `graph_read` | 綁定的快照、revision、view → Graph／Flat 完整文字，或研究檢視所需的節點、證據與路徑 | 正式預測器由 host 一次送入固定文字。互動查鄰居、檢索、詢問例外歸在另外的研究條件。 |
| 預測器 · `predict` | 相同背景、指定表示、英文原題、選項或量尺／理由 → 原始回答、用量、狀態 | 分離的全新工作階段，逐題作答，查詢條件用完即丟。builder 和 predictor 即使用同一模型快照也不共享訊息。 |
| 研究者 · `trace_read`；scorer 對分 | run、item、revision／事件區間 → 提議、退回、提交、引用與實際輸入。已交卷後才用 item ID 對上封存答案 | 模型提出的修訂、研究者盲審意見與真人作答，保留不同作者。操作紀錄描述外部動作與證據，無需模型內部思考。 |

**寫入動詞。** 用 `upsert_concept` 記概念或有證據的別名。`add_condition` 提議條件、父條件及這次為何需要新節點，`add_claim / attach_evidence / challenge_claim` 用來建立、支持或質疑主張。P46 的子情境只建一次，再用 `add_exception(local_claim=R2, default_claim=R1, evidence=[e005])` 記下何處改判。Host 將建立緣由留在首次提交的事件。本人可以挑一條推論提出更正，將更正記為由本人提供的新證據。若確認誤讀，`retract_claim` 撤回該解讀，可連到替代主張；原始引文保留，依賴它的主張與例外連結逐一重評。本人說同條件下想法改變才用 `supersede_rule`。HugAgent 現有訪談沒有本人看圖後更正的資料，這個流程可先用合成對話驗收。

**一個具體呼叫。** 假設原話 `e001.answer` 完整為 `I prefer a short report on Fridays.`。同工作階段已有 `short_report` 概念與 `friday` 條件。以下是合成資料；參數示範留出第一輪允許的最小寫法。

```json
{
  "request_id": "draft-07",
  "expected_revision": 2,
  "operations": [{
    "op": "add_claim",
    "temp_id": "r1",
    "holder": "participant",
    "about": "self",
    "relation": "stance_on",
    "args": {"target": "short_report"},
    "outcome": "positive",
    "condition_id": "friday",
    "basis": "explicit",
    "applicability": "usual",
    "evidence": [{"id": "e001", "field": "answer", "quote": "I prefer a short report on Fridays."}]
  }]
}
```

主程式從 evidence 欄位取得發話者。成功時 `graph_propose` 回 `{ "draft_id": "d7", "base_revision": 2 }`；host 提交可回 `{ "revision": 3, "id_map": { "r1": "c9" }, "event_seq": 18 }`。若改寫成「週五短報勝過詳細報」，原話並沒有指定詳細報這個對手。即使引文和兩端 ID 都存在，仍是可能通過格式檢查的**語義錯誤**，應由盲審標出。可給 builder 的任務句是「用引用支持每條判斷，保留說話者、對象、條件與程度；分清明說與推論。材料不足時回報缺口。」實際建圖與渲染用英文，中文只作研究者閱讀。

**預測器讀到的差別**也可用上面的自造句看。Graph 會出現類似 `C1 = short report | K1 = Friday | c9: participant, about self, stance_on(C1) = positive, usual when K1, explicit` 的記錄；Flat 則會寫成 `The participant explicitly says they generally favor a short report on Fridays.`。兩者都附相同的 `e001.answer` 引文。同一個 C1 若出現在另一條規則，Graph 直接連回 C1，Flat 在新句中再次寫明 short report。兩者都只有證據支持的語義，Raw 另外保有問答全文。

**後續若把樹開放給 LLM 查詢**，可沿用 `graph_read(view="resolve", revision, question_slot, conditions)`。例如傳入「交通變化」與「便宜＝真、可及性＝未知」，結果包含 `provisional: [R1], possible_exceptions: [R2], missing: [accessible], evidence: [e005]`。輸入內容隨查詢丟棄，回覆保留被取代／未決的規則與原因，讓讀者知道再問什麼會改變結論。主實驗的 runner 僅開放整份 Graph 或 Flat 的固定讀法。

**驗證、重試與重播。** Host 檢查角色、同一訪談、端點型別、條件環、覆寫方向與 claim 相容性，並用欄位內 Unicode code point 的半開區間定位原話；引文多次出現時要求提供可驗證的起訖。回覆如 `SPAN_AMBIGUOUS` 可帶同工作階段的位置，`OUT_OF_SCOPE` 不帶其他訪談內容，`STALE_REVISION` 回當前版本供重新提議。同一工作階段同一 request ID、相同內容重送取得原結果，不同內容須換新 ID。一批失敗保留拒絕紀錄，圖維持原版。首選一批完成抽取；修正輪數、輸出上限、失敗計分與成本在 run 前凍結。

每個事件記工作階段、單調序號、actor、request、操作／錯誤、前後 revision、可還原的提交內容、暫時到穩定 ID 對照、證據、設定指紋與用量。離線重播**已提交的操作**應重得同一快照內容雜湊。快取鍵含資料版、人／域與有序證據指紋、builder 快照及 prompt／schema／設定版本。renderer 另存版本、實際送入文字及雜湊。等同快照可以重用；修改研究者的判讀另開版本，已作答的 run 仍能還原。

## 怎麼讓第一輪真的測到你的問題

| 組別 | 預測器實際讀什麼 | 能檢驗什麼 |
|---|---|---|
| Raw | 官方完整英文 prompt 中，本題允許的全部 QA | 同一模型直接讀這個人的話能預測多準 |
| Graph | 明列概念 ID、具角色的關係、條件、依據與短引文的英文文字 | Graph 對 Raw 是抽取、組織與讀圖一起帶來的淨效果 |
| Flat | 從同一凍結快照逐條展開成獨立英文句。展開「誰對誰有什麼影響」及「哪種條件覆寫哪條規則」，以相同短引文作結 | Graph 對 Flat 檢驗同一批語義用顯式連結呈現的效果。圖的文字編碼會影響模型表現。[Talk Like a Graph](https://research.google/pubs/talk-like-a-graph-encoding-graphs-for-large-language-models/) |

**三組怎麼保持可比。** 固定預測模型快照、題目、人口背景、選項／理由與量尺、解碼和輸出上限。Graph 與 Flat 由同一串有序主張生成，程式逐筆核對兩者覆蓋的語義、例外、引用範圍和順序；各組均完整讀完、一次作答，同時記實際 token。Graph 可以把同一概念顯式連到多條主張；Flat 在每句重述必要的實體與條件。沒有進入任何主張的概念標籤與建圖診斷不另塞給 Graph。正式預測不疊加互動查圖或黃金情境標籤。

兩種表示使用同一個快照選取規則。現行主張與有根據的衝突雙方都呈現，並標出爭議；已撤回的解讀只在研究者歷史檢視出現。有時間證據的舊規則保有適用期間，按所問時點讀取；HugAgent 第一輪沒有足夠的跨時變更標籤。尚待核實的例外連結只供稽核，其底下各自有依據的局部觀察仍可進兩組。原文定位與欄位型別通過，僅代表操作有效；主張是否忠實屬另一項人工判讀。

**這一輪的量。** 54 人、1,742 題（T1 356、T2 1,386），每種表示各答 1,742 次；Graph 與 Flat 共用以本人、領域、完整有序可見 QA 去重的 460 份建圖輸入。最多 460 份成功快照，builder 工具輪次另算。保留 T1 官方方向正確率、T2 官方正規化平均絕對誤差為兩個主要指標，逐人配對、三域等權，T2 再拆立場、情境、經驗及理由。另看 994 對同情境理由的分數排序，這只衡量「哪個理由影響較大」。同一對同措辭理由能跨兩個情境比較的只有 19 組，嚴格反轉為 0；P46 的真例子正好提醒我們，**因果判斷可以有例外，即使理由排序沒有翻轉**。[資料與評分核對](hugagent/prepared-data.md) · [排序配對與樣本限制](hugagent/HugAgent-54-Research-Design.md#9哪些構想值得等到下一步)

**什麼結果值得開 Tree 實驗？** 盲審先找出同一主體、同一判斷、有父預設與可辨子條件的案例，再檢查錯誤是否集中於「需要的兩條規則都在，卻選錯適用條件」。若出現這種錯，固定同一份凍結規則與預算，比較平面規則匹配和樹狀繼承／覆寫；獨立量選中規則是否正確、最後預測誤差、可判定案例數與覆蓋率。兩種機械路由在同規則同語義下若等價，應得相同結論；要測 LLM 是否更會讀樹，就固定內容只改規則的呈現。真人資料不足時，用自造最小對驗證機制，把真人表現另列。已看過的 P07、P46 用於講解與稽核，不用它們的答案調 prompt。[W8 第 10 頁](../meetings/w8.pdf#page=10)

### 審圖時，第一個畫面該讓你做到什麼

點「同一題 Raw 誤差較小、Graph 較大」→ 左邊按原序看該題 QA，中間展開這一棵樹的子情境。選「只看有例外的規則」可高亮改判的位置，點開就看見一般判斷、局部判斷與原句。右邊比對三組實際讀到的英文與回答，底下顯示哪次操作把它寫成這樣。可標「漏抽、談錯人、條件被放寬、程度被壓平、圖正確但答錯、資料不足／原因未明」。預設隱藏真人答案；另抽三組同答的例子，才看得到「分數答對、其實圖解讀錯人」的情形。正式圖與盲審修正用不同版本。研究用本機匿名資料；對外展示與未來本人互動介面可用合成例子。[研究資料使用範圍](../ref/HugAgent/prepared/LICENSE)

## 可以走得更遠的幾條路

| 你可以問的研究問題 | 最小的實驗 | 結果能告訴你什麼 |
|---|---|---|
| **這張圖究竟記住了誰？** | 另做同域配對，在同一題與同一人口背景下，替換成另一人的允許訪談表示。預先匹配訪談長度、題型遮蔽與可用線索，排除會帶入目標答案的配對。 | 本人的材料能否比相似他人的材料多提供個人線索。可比較這個差值在 Raw／Graph 是否不同。 |
| **哪一個條件真的讓他改判？** | 自造四個只改一個條件的案例，覆蓋 P46 型的「便宜 × 可及」四格，再加一組條件未知。預先標明哪條規則應啟用及哪些其他判斷應保持。 | 可分開測「知道何時套例外」和「碰巧猜對最後選項」，也能發現模型把「且」誤讀為「或」。 |
| **下一句最值得問什麼？** | W8 工廠例缺「本週 × 一般風險」這格。同意參與的未來受試者可被問「如果今天回到一般風險，還想增產嗎？」比較模型選問與制式追問，每人相同次數，再評後續新題。 | 衡量多問一句是否真的有助於區分情境例外與偏好改變。第一輪 HugAgent 沒有回訪這項觀察。 |
| **當我說『你理解錯了』，它改對哪裡？** | 在合成對話或新取得同意的資料裡，本人可標「我講的是別人」「只在那班夜班」「我現在改了」。凍結一批應改與應穩定的舊題，比更正前後。 | 直接測 LLMe 可不可以接受本人糾正，同時保住仍有效的其他判斷。 |
| **兩張都說得通的圖，差在哪一句？** | 將同一段話的兩個有根據的解讀分列為待驗假說。找出它們對哪道新題會給不同預測，再盲測；或抽掉唯一支持某結論的引文，看哪些依賴真的失去支持。 | 找到資料能區分的解讀和目前無法分辨之處，避免把一張畫得合理的圖當成唯一答案。 |
| **一條規則能跨域嗎？** | 沿用已約定的醫療 → 監控、監控 → 都市分區、都市分區 → 醫療，只讀同人的來源域證據。抽樣核對遷移前後是否還在說同一條規則。 | 「有其他領域的訪談能否預測更準」可用分數回答；「是哪條個人取捨真的通用」需要可核對的規則與來源。[跨域設計](hugagent/round-one.md) |

通用層做到「來源可回查、主張有角色、條件有範圍、修訂可重播」。下一個 dataset 若有直接選擇、同條件跨時觀察或本人更正，可由 adapter 宣告這些證據能力，再開對應操作與評測。模型參數編輯是 W7 的另一個長期問題；到時可以撤下外部圖，測它是否依然記得例外，並查更正一條規則會不會動到其他選擇。[W7 第 10、13 頁](../meetings/W7.pdf#page=13)

| **大情境的含義已澄清，分層方式待審** | 根涵蓋本人所有情況。可從議題或生活角色進入，再看局部條件、被覆寫的主張與該節點的子圖。HugAgent 先以三議題瀏覽，作答遵守逐題證據邊界。 |
| **混合分支與雙樹，待整體審核** | 可以按不同緣由長出兄弟節點。情境包含與例外覆寫分別查詢，以完整條件判斷哪些規則生效。介面可以合畫；例外關係有多層時可另行展開。 |
| **已同意** | 容許模型寫有原話支撐、明標為推論、本人可以糾正的主張。例如「這次他可能更看重安全」。更正可以只針對模型猜的理由，原本的選擇依然保留。 |
| **待決定** | 已知他說「通常願意增產」，另一段說「這次可能永久傷人，我選擇維持」。可以標記「永久傷害可能是例外」為推論。第一輪 Graph／Flat 要將兩段連成「遇到永久傷害就改判」交給預測器嗎？本稿建議保留兩段有據的主張，覆寫連結先列候選，等原話直接支持這層關係再收入正式表示。 |

研究者核定整體設計後，才凍結 schema、工具與三組呈現。本稿的真人例子是以可見訪談人工對照的設計示意。
