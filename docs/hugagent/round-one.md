## 第一輪架構與可檢驗的差異

1. **切資料。** Adapter 先分出 HistoryView（題內有序 QA）、PredictionView（同一背景、原題與選項或量尺、指定理由）、ScoringView（真人答案、T1 遮蔽 QA 及標註）。Host 掌握 ID、domain 和路由。建圖器不看待預測問題。題幹內的條件只在該題查詢時存在。
2. **建圖並凍結。** HistoryView 經 builder 提議操作、host 驗證、原子提交，輸出 frozen snapshot。區分「可存取的訪談範圍」和「主張適用的條件」。前者參與 cache key；後者屬於 Claim 語義。在相同證據與相同 builder 設定下才可跨題重用。
3. **改變表示。** Raw 重現官方完整 prompt。Graph 把 QA 區換成具角色、方向、共用節點、條件和引文的文字編碼。Flat 將同一張圖的每條 typed claim 逐一轉成獨立句子，完整保留關係兩端、方向、談論對象、否定、別名、強度、條件與引文。固定順序政策，核對 claim ID 與引用範圍逐條對應。預測器的快照、背景、原題、解碼設定均固定，每題每臂一次作答。主表用能容納最長實際 payload 的視窗，避免靜默截斷。
4. **比較。** Graph−Raw 衡量「抽取加上讀圖」的淨效果；Graph−Flat 衡量這種圖編碼在相同抽取內容上的額外效果。三組共 5,226 個預測；另有最多需處理的 460 份不同訪談，模型請求數還取決於工具輪數、重試和快取。分別報首次建圖與重用成本、實際 tokens、失敗率。網站畫出的圖與模型實際閱讀的文字，都要能查到同一 revision。
5. **計分。** 兩項主要終點為三域等權 T1 accuracy（差值正為改善）與三域等權 T2 normalized MAE（差值負為改善）。另報官方容差、方向與 ATI，以及 T2 基準、其他 opinion、理由評分三組。其他 opinion 可再按上表題意細看。對 54 位受訪者做配對 cluster bootstrap，預定 5,000 次，保留同人所有題目及三組結果，重抽複本不去重。逐項報 95% 區間，跨零只表示仍有不確定性。若打算任一項顯著就宣布整體成功，需在揭露結果前訂多重比較規則。
6. **區分錯答與失敗。** 上游 T1 parser 掃字母，T2 取首個符合規則的數字，不檢查整句格式及量尺。交原始文字或 null，另報嚴格格式／越界率。缺答於 BSI 與 BDU 容差計錯，BDU MAE 計 6。方向只計自身基準與情境皆有可解析預測的配對，各臂另報有效分母及三臂共同有效子集。建圖失敗保留所有受影響題次並註明原因；合法的零主張圖則正常渲染與預測。

## 操作紀錄與檢視器如何用於研究

採 MCP 風格的本機工具合約。builder 透過 `evidence_read` 讀 host 綁定的 QA，以 `graph_propose` 送一批帶 request ID、預期 revision、證據與引文的操作；只有 host 可 `graph_commit`。預測 runner 只讀 `graph_read` 的固定快照；研究者由 `trace_read` 查事件。完整 schema 候選、fixture 與錯誤格式見[實作原稿 §3–4](LLME-Implementation-Prompt.md)。

操作紀錄保留可取回的已提交操作、暫時到穩定 ID 的映射、前後 revision、證據、模型設定、結果或拒絕碼及順序。傳輸重送沿用同一 request ID；修過內容的提議用新 ID 連回被拒的原事件。確定性重播僅套用 committed ops，不呼叫 LLM，應還原相同內容 hash。時間戳、用量和延遲留在事件 metadata。字面引文可驗證來源位置；「引文是否真的支持主張」另由人審。

研究者的第一個使用路徑是「總覽選分歧 → 打開同一道題 → 點 claim 回到原句 → 看當時提交了什麼」。桌面左側原序 QA、中間穩定布局的圖、右側題目／三臂預測與選取主張，底部為建圖操作軸；手機切成頁籤並保留選取。T2 的「對／錯」明標官方容差，另可篩同題誤差較大者。UI 應能區分漏抽、對象弄錯、方向或強度丟失、過度泛化、圖中有證據但預測仍錯，以及原始證據不足。允許「原因未明」。能呈現模型可見資料，無法由點擊的引文證明模型實際採用了它。圖忠實度抽查宜同時納入三臂同答與分歧題，預先抽樣、先隱藏 gold，避免只用醒目的錯例估整體品質。

## 正式執行前值得討論

- 若 T1 改善但理由強度退步，建議逐項解讀。若未來要主張「同樣準而更便宜」，需要預先定義可接受的誤差差距，並選定首次建圖或重複使用的成本口徑。
- 若 Graph 與 Flat 一起勝 Raw，最直接的下一題是「整理成普通文字是否已足夠」。若圖常漏掉短答的問句或把一般人當本人，先看抽取忠實度；若證據都在而特定條件經常被套錯，再挑有父子規則的樣本測 Tree。
- 正式跑前固定可用的模型快照、provider、輸入上限、估計成本與預算。預先寫下哪些資料已看過；用合成材料開發，真人錯題導出的修改另建探索性版本。
